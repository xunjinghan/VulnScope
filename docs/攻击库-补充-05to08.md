## 05 文件上传 → RCE

**探测**
- 找到所有上传点（头像/附件/导入/富文本图片）`[实测]`
- 传一个正常文件确认接口可用，再逐项试探：`.php .jsp .asp .aspx .phtml`、双后缀（`a.php.jpg`）、大小写（`.PHP`）、`%00` 截断、`.htaccess` `[实测]`
- 同时看**返回体里是否回显保存后的路径/文件名**（有回显就能直接定位落地位置）`[实测]`

**验证判据**（关键：不只看"传上去了"）
- 文件确实落地 **且能被直接访问** → 取回内容与上传内容一致 `[实测]`
- 在 PHP/JSP 等解析环境下该后缀会被执行 → 等于 WebShell `[实测：靶场回取 shell.php 原文即证明]`
- 更强的判据：上传后访问时**执行结果带唯一标记**（如打印 `MARK` 字符串）

**常见绕过** `[清单]`
- 前端校验 → 直接改包绕过 `[实测有效]`
- 后缀黑名单 → 换等价后缀（`.phtml/.php5/.pht`）、双写（`.pphphp`）、大小写、末尾点/空格（Windows）
- Content-Type 校验 → 改成 `image/png`
- 文件头校验 → 在脚本前加 GIF89a 魔术字节
- 上传目录可访问但不可执行 → 找包含/解析链（`.htaccess`、`user.ini`）

**修复**
- 后缀白名单 + MIME + 文件头三重校验；重命名为随机名（不含用户可控部分）
- 上传目录**禁止执行**，且不放在 Web 根（或走独立域名/存储）
- 限制大小与类型；图片做二次渲染

## 06 SSRF

**探测** `[实测]`
- 找出所有"服务端代你访问 URL"的功能：图片抓取、Webhook、URL 预览、PDF 导出、导入外部数据
- **对照实验**：同一个 URL，直连 vs 经该功能 → 前者 403、后者 200 就是 SSRF `[实测用法]`
- 内网探测：`127.0.0.1`、`localhost`、`169.254.169.254`（云元数据）、内网网段段扫 `[清单]`
- 协议探测：`file://`、`gopher://`、`dict://` `[清单]`

**验证判据**
- 服务端能访问**外部客户端访问不到**的资源，并把它回显给你 `[实测]`
- 或在响应时间/错误信息上形成可靠的盲 SSRF 侧信道 `[清单]`

**常见绕过** `[清单]`
- 黑名单绕过：`127.0.0.1` → `127.1`、`0.0.0.0`、十进制/八进制 IP、`[::1]`、`①②⑦.⓪.⓪.①`
- DNS 重绑定（先用合法域名通过校验，再解析到内网）
- 302 跳转绕过（校验前段、跳转到内网）
- 只校验字符串开头 → `http://evil.com@127.0.0.1/`

**修复**
- **URL 白名单**（域名+协议+端口），不用黑名单；禁止跳转
- 出网走统一代理并限制目标网段；禁访问元数据地址（云上开 IMDSv2）`[清单]`
- 解析后的 IP 再做一次校验（防 DNS 重绑定）`[清单]`

## 07 敏感信息泄露 / 凭据泄露

**探测** `[实测] [清单]`
- 常见路径批量探测：`/config.json` `/backup.zip` `/.git/config` `/.env` `/www.zip` `/db.sql`
  另有 `.bak .swp .old ~ .tar.gz .svn .DS_Store WEB-INF phpinfo` `[清单]`
- **JS 里找硬编码密钥与接口**（`[实测]`：灰产 App 案例即靠这条挖出域名）`[清单]`
- 错误页/堆栈泄露绝对路径、SQL 语句、内网 IP `[实测：注入靶场 S2 命中]`

**验证判据**（必须证明"可用"）
- 文件无需认证即可下载，且内容**真实包含凭据**（AK/SK、DB 连接串、JWT 密钥）`[实测]`
- 备份包能解压并含源码/数据 `[清单]`
- 进一步验证凭据可用范围（云 AK 能否列资源、DB 能否连）——**注意：仅在授权范围内做最小验证** `[清单+红线]`

**扩展取证手段** `[清单]`
- `.git` 泄露 → **git-dumper** 还原完整源码
- 前端 **SourceMap（.map）** 还原源码与接口
- **Wayback Machine / CDN 缓存 / 搜索引擎缓存**取历史页面（可能暴露已删除的接口）⭐
- 仓库审计工具：**gitleaks、trufflehog**

**修复**
- 敏感文件移出 Web 根并加访问控制；Nginx/Apache 屏蔽 `.git/.env/*.zip/*.sql/*.bak`
- 密钥走环境变量/密钥管理服务（KMS），不入库不入仓；**泄露立即吊销轮换**
- 关闭目录列表与详细错误页，统一错误响应

## 08 存储型 XSS

**探测** `[实测] [清单]`
- 找到所有**入库后再展示**的输入点：评论、昵称、签名、留言、资料、工单
- 提交唯一标记 payload：`<script>XSS_STORE_MARK_3344</script>` `[实测]`
- **触发面要全找**：列表页、详情页、后台管理、邮件通知、**导出 PDF/Excel** `[清单]`

**验证判据**（存储型的关键是"持久 + 他人可见"）
- 重新 GET 页面时 payload **以未转义原文**出现在 HTML 中 `[实测]`
- 换一个浏览器/账号访问同一页面仍触发（证明是存储型而非反射型）`[清单]`
- 最好能证明**影响管理端**（这才是给钱的等级）`[清单]`

**常见绕过** `[清单]`
- 标签：`<svg>`、`<iframe>`、`<body onload>`、`<details open ontoggle>`
- 事件：`onerror`、`onfocus`、`onmouseover`、`onanimationstart`
- 关键字过滤：大小写混写、嵌套拆分、Unicode、HTML 实体、URL 编码
- 上下文绕过：属性值闭合、JS 字符串内 `\` 转义、`href="javascript:"`

**修复**
- **按输出上下文分别编码**（HTML 实体 / 属性 / JS / URL）
- 富文本用成熟库净化（**DOMPurify**），配白名单
- **CSP** 禁 inline script 与 eval（纵深防御）
- Cookie 加 `HttpOnly / Secure / SameSite` 降低窃取危害

## 本轮实测成绩（自建靶场 weblab2.py）

| ID | 漏洞 | 等级 | 判据 |
|---|---|---|---|
| U1 | 上传未校验类型、脚本落地且可直接访问（可致 RCE） | 严重 | 传 `shell.php` → 200 保存 → `GET /uploads/shell.php` 取回原文 |
| U2 | 上传文件名可穿越（穿出 Web 根） | 高 | `filename=../../traversed_outside.txt` → 文件落在 Web 根之外 |
| S1 | SSRF（服务端代请求访问内部接口） | 高 | 直连 `/internal/secret` = 403；经 `/fetch?url=` = 200 且读到内部数据 |
| L1 | 敏感文件可公开下载（含云 AK/SK 与 DB 口令） | 严重 | `/config.json` `/backup.zip` `/.git/config` 均 200，含 `LTAI5t…9527` 与 `root:P@ssw0rd` |
| X1 | 存储型 XSS（原样入库+原样回显） | 高 | 提交后重新拉取页面，payload 以未转义原文出现 |

## 本轮踩到的坑（已入库）
1. 上传穿越的检测路径算错（`../` 落在 Web 根内）→ **穿越测试必须算清最终落点**，要穿到根目录之外才算
2. SSRF 判据要用**对照实验**（直连被拒 + 经服务端成功），单看"能访问"会被误判
