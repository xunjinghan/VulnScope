# DSH 漏洞挖掘 PLAYBOOK（总纲）

> 每次开工**先读本文件**，再读 `brief.py` 输出的简报。
> 这是"能力累积"的唯一载体——会话会关，文件不会。

---

## 0. 铁律（违反即停手）

1. **只在授权范围内测试**。范围来自项目页面的明文 scope；范围外的资产一律不碰（含同一公司的兄弟域名）。
2. **不做破坏性测试**：不删改数据、不植入后门、不上传 webshell 到生产、不发起 DoS/压力测试、不横向到范围外主机。
3. **不碰个人数据**：发现 PII/凭据时，**只记录证据类型与数量级，不下载、不落地、不外传**。
4. **真实目标必须走 `scope.json` 白名单**：`guard.py` 默认只允许内网；对外目标要先写入 `scope.json` 并人工确认。
5. **不作恶、不炫技、不越权**。任何"顺手再试试"的冲动都要先回到范围定义。

## 1. 标准工作流（七步，缺一不可）

| 步 | 动作 | 产出 |
|---|---|---|
| 1 **确认授权** | 抄录项目 scope（域名/IP/APP/时间窗）+ 确认账号有权限 | `scope.json` |
| 2 **资产测绘** | 子域/端口/指纹/接口/JS 提取 → 资产清单 | `assets.json` |
| 3 **分类攻击** | 按 §3 的漏洞矩阵逐类试（每类留证据） | `findings.json` |
| 4 **验证** | 每条发现都要**可复现**：命令 + 请求 + 响应片段 | 复现记录 |
| 5 **定级** | 按 §4 判危害等级，**低危直接丢弃**（不收钱还占用时间） | 定级结果 |
| 6 **查重** | 对照已知公开漏洞/项目历史/常识 | 查重结论 |
| 7 **报告 + 入库** | `report_gen.py` 出报告；`kdb.py` 写库 | 报告 + DB 记录 |

> **每轮结束必须写库**（techniques / lessons / campaigns / findings）。不写库 = 这一轮白打。

## 3. 漏洞矩阵（按价值排序，先打上面的）

**A. 必打（高价值）**
- 认证绕过 / 越权：IDOR（水平+垂直）、JWT 缺陷、会话可预测、密码重置逻辑
- 注入到 RCE：SQLi（有数据/可写文件）、命令注入、SSTI、反序列化、文件上传
- 服务端请求伪造（SSRF）→ 内网访问 / 云元数据
- 业务逻辑：支付篡改、负数、竞态(TOCTOU)、状态机绕过、幂等缺失
- 敏感信息：凭据硬编码、配置泄露、云 AK/SK

**B. 次打（中价值，视项目而定）**
- 存储型 XSS（能打到管理员才算）、CSRF（有实际后果的）、路径穿越、XXE、CORS+凭据

**C. 不收（低价值，别浪费时间）**
- 缺安全响应头、self-XSS、仅版本号泄露、需要用户交互的反射型 XSS、点击劫持（单页）

## 4. 危害定级（决定收不收钱）

| 级别 | 判据 | 处理 |
|---|---|---|
| 严重 | 未授权 RCE / 全量数据 / 认证绕过进后台 | 立即出报告，标最高优先级 |
| 高 | 越权读写他人数据 / SQLi 取库 / SSRF 进内网 | 出报告 |
| 中 | 存储型 XSS 打管理端 / 逻辑缺陷可获利 | 出报告 |
| 低 | 缺响应头 / 信息泄露无敏感内容 / self-XSS | **丢弃**（除非项目明确收） |

---

## 5. 报告标准（漏洞盒子可提交级别）

必含：**标题 / 危害等级 / 影响资产 / 复现步骤（可复制命令或请求包）/ 证据截图或响应片段 / 危害说明 / 修复建议**
禁止：夸大危害、编造复现步骤、包含无关的他人数据。

用 `python report_gen.py --findings <json> --project <名> --target <目标>` 生成骨架，再人工润色。

---

## 6. 坑库（血泪索引，详细见 `kdb.py report` 的 lessons 表）

- 改代码不重启 = 验证无效（Python 跑内存旧码）→ 每次核 `md5`
- `urllib` 默认跟随 302 → 把"跳转登录页"误判成"可访问"（探测可访问性要 no-redirect）
- 判据过松（`len(body)>40` 当堆栈判据）→ 假阳性
- 硬编码端点做成功标志（`/profile` vs `/home`）→ 误判
- dex 字符串计数 ≠ 行为证据（库代码也会命中）→ 必须反编译看调用点
- 下载字节数异常小（<1KB）先怀疑 URL 404（"Not Found" 正好 9 字节）
- 同一资源两个管理者 → 互相打架
- Kali 装包必须先 `apt update`；镜像 403 就换 `http.kali.org`
- VM(NAT) 下不了 GitHub Release 资产（9 字节）→ 主机下载再 copyto

## 7. 自进化机制

```
每轮攻击 → 结果写入 findings（含证据）
        → 新手法写入 techniques（含 howto）
        → 失败/误判写入 lessons（含根因与修正）
        → 整轮写入 campaigns（含指纹与命中率）
下次开工 → brief.py 自动带出最近教训与技术清单
```

**目标**：让"下一轮"永远比"这一轮"强一点，且这个提升**落在文件里**，不随会话消失。
