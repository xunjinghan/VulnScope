## 三、通用检查清单（下一轮按这个打）

### A. 认证与会话
- [ ] 登录后 session 是否轮换（防固定）✅ 本轮已验证防住
- [ ] Cookie 是否 HttpOnly / SameSite / Secure（HTTPS 时）
- [ ] 会话过期时间是否合理、有无并发会话控制
- [ ] 改密后是否全局踢下线
- [ ] 密码复杂度、是否有登录失败锁定（**不主动爆破**，只看策略）
- [ ] 注册接口是否可无限调用（**未测，避免产生数据**）

### B. 授权（越权是重点）
- [ ] 水平越权：换对象 id / 换 user_id / 换订单号
- [ ] 垂直越权：低权限账号访问管理接口
- [ ] 接口是否有未授权访问（去掉 Cookie 再请求）
- [ ] 批量赋值（mass assignment）：多提交字段看是否被接受（**写操作，需先获授权**）
- [ ] 参数污染：`?id=1&id=2`、数组形态 `id[]=`

### C. 输入处理
- [ ] SQL 注入（报错/布尔/时间三类，**只用只读载荷**）
- [ ] XSS（反射/存储/DOM）—— DOM 型需真浏览器
- [ ] SSTI / 命令注入 / 路径穿越
- [ ] 参数类型与长度边界（此前 `id=1'` 已被 400 拒绝）✅
- [ ] 异常处理是否回显堆栈 ✅ 本轮已防住

### D. 业务逻辑
- [ ] 订单金额/数量篡改
- [ ] 优惠券/积分无限领取
- [ ] 验证码复用、短信轰炸
- [ ] 并发竞态（**只读场景可测，写场景不测**）

### E. 信息泄露
- [ ] 状态码差异导致的存在性枚举（**本轮真实命中 2 条**）
- [ ] 错误页、注释、JS 里的接口与密钥
- [ ] 敏感文件（.git/.env/备份/数据库）
- [ ] 安全响应头缺失 ✅ 本轮已齐全

## 五、AI 辅助挖洞的现状（IEEE 综述要点）

- **效果取决于两件事**：① 上下文接地质量（RAG/摘要/校验器）② 编排纪律（角色分工/计划/反思）
- 纯"把源码丢给 LLM"效果有限；**带工具（爬虫+验证器）的 Agent 编排**收益明显
- 本项目的实践正好印证：`scan.py`（AI 只做判定）+ `verify.py`/`recon_extra.py`（机器做验证）
  比"让 AI 直接下结论"可靠 —— **AI 出线索，机器出证据，人做复核**

## 六、下一轮具体打法（针对豆包的新版本）

1. 先跑 `recon_extra.py`（敏感路径/方法/会话固定）—— 它可能会新增端点
2. 再跑 `scan.py` + `verify.py`（未登录面自动验证）
3. `targeted_attack.py`（注入/CSRF/XSS/参数/枚举，**含新增的枚举检查**）
4. `auth_attack.py`（带会话越权，属主由响应推导）
5. 重点盯它这轮的修复点：**统一 404？限速改三重？密码复杂度？改密踢下线？**
6. 若它引入了新功能（如 admin 角色、文件上传），就针对新面打 —— **新代码=新攻击面**
