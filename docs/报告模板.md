# 漏洞报告标准模板（提交前照此自查）

> 用途：所有项目报告统一结构，保证"厂商能复现、能判级、能直接发钱"。
> 生成流程：`armor.py check` → `recon.py` → 人工探测 → `findings.json` → `armor.py sev` → `enrich.py` → `report_gen.py` → **本模板自查** → 提交

---

## 一、报告必须有的 6 个部分（缺一不可）

| # | 部分 | 硬性要求 |
|---|---|---|
| 1 | **漏洞汇总表** | 每条：名称 / 类别 / 等级 / 影响资产；按等级降序 |
| 2 | **漏洞详情** | 描述 + 复现步骤 + 证据 + 危害说明 + 修复建议（五小节齐全） |
| 3 | **复现步骤** | **可复制粘贴**的命令/请求包；含必要 header；从零开始能走通 |
| 4 | **证据** | 原始响应片段（打码 PII 但保留可辨识结构）；带时间戳；**只放最少样例（2–3 条）** |
| 5 | **危害说明** | 写**实测到的**后果（"读到 3 条他人订单"），不写"可能导致" |
| 6 | **修复建议** | 具体到实现（"取资源时校验 owner_id == session.uid"），不写"加强安全" |

---

## 二、每条漏洞的写法（示例对照）

### ❌ 不合格
> **标题**：存在 SQL 注入
> **描述**：网站有 SQL 注入漏洞，危害很大。
> **复现**：我在 id 参数加了单引号就报错了。
> **修复**：建议修复。

问题：无等级、无对照证据、不可复现、无实测危害、修复无内容。

### ✅ 合格
> **标题**：商品详情接口 SQL 注入（可 UNION 读取 users 表凭据）
> **等级**：严重（CVSS 9.1）
> **资产**：https://target.example/api/product
> **描述**：`id` 参数未参数化，直接拼接进 SQL 查询，导致可注入。
> **复现步骤**：
> 1. 基线：`GET /api/product?id=1` → 返回 1 行
> 2. 布尔验证：`GET /api/product?id=1 OR 1=1` → 返回 **3 行**（条件被注入改变结果集）
> 3. 取数：`GET /api/product?id=0 UNION SELECT 1,name,2 FROM users` → 返回 `admin|alice|bob`
> **证据**：步骤 3 的原始响应体（截取前 3 行，含用户名字段）
> **危害说明**：实测可读取 `users` 表的用户名，同一注入点可继续读取 `pass_hash` 字段，
> 结合离线破解即可获得账号口令，进而登录后台。
> **修复建议**：全部 SQL 使用参数化查询（`cursor.execute("... WHERE id = ?", (pid,))`）；
> 数据库账号仅授予必要权限；关闭详细报错回显。

## 三、等级判定参考

| 等级 | 典型情形 |
|---|---|
| **严重** | 可 RCE / 可读全量数据 / 可伪造管理员 / 支付逻辑可任意改额 / 云 AK 泄露 |
| **高危** | 越权读写他人数据 / 存储型 XSS 打到后台 / SSRF 可达内网 / 路径穿越读敏感文件 |
| **中危** | 需交互的越权 / 报错信息泄露 / 登出未失效 / 无速率限制 |
| **低危** | 缺安全响应头 / 版本号泄露 / self-XSS / 需极端前提 —— **一般不值得提交** |

## 四、提交前 10 条自查（逐条打勾）

1. [ ] 目标在项目 **scope 内**，且不在 out_of_scope 列表
2. [ ] 每条漏洞都有**基线对照组**（不是"看起来有问题"）
3. [ ] 命令注入/反射类有**唯一标记串**证明
4. [ ] 穿越/上传类**算清了真实落点**
5. [ ] 判"他人数据"看的是**属主字段**，不是猜 id 顺序
6. [ ] 探测可访问性用了 **no-redirect**
7. [ ] 证据里 **PII 已打码**，且**只放最少样例（2–3 条）**
8. [ ] 危害写的是**实测结果**，没有"可能/也许"
9. [ ] 修复建议**具体到代码或配置项**
10. [ ] 已**查重**（平台历史/公开披露），确认不是重复提交

---

## 五、常见驳回原因（按出现频率）

| 驳回原因 | 预防 |
|---|---|
| 无法复现 | 步骤写全（含 header/前置状态），自己从零走一遍 |
| 非漏洞（self-XSS、缺响应头） | 提交前对照第三部分的"低危"清单过滤 |
| 重复提交 | 第 10 条自查 |
| 危害描述不成立 | 只写实测到的后果 |
| 越界（超出 scope） | 第 1 条自查 + `armor.py` 过闸 |
| 证据不足/全是"可能" | 第 2、3、8 条自查 |
