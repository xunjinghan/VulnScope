## 这是什么？

VulnHunt 是一个**四步流水线**的自动化漏洞挖掘工具集：

```
目标 URL → 爬虫(crawl) → AI判定(llm) → 非破坏性验证(verify) → 报告(report)
```

它不是另一个 sqlmap 或 nuclei。它的核心价值是：

- **AI 辅助判定**：用大模型分析攻击面，给出漏洞类型、可能性和理由
- **非破坏性验证**：真发请求证明漏洞，但三条禁令写死在代码里（不改数据、不爆破、默认只读）
- **安全护栏**：只允许 localhost/内网，公网目标一律拒绝
- **自带烟测靶场**：`labtest/app.py` 故意埋了 6 类洞，开箱即测

## 一分钟上手

```bash
# 1) 启动自带烟测靶场（故意埋洞的最小站点）
python labtest/app.py 8099

# 2) 启动 AI 大脑（需要豆包桌面版 + CDP 调试端口）
# （或配置其他 OpenAI 兼容 API）

# 3) 开扫
python scan.py http://127.0.0.1:8099/ --max-pages 10

# 4) 验证（非破坏性）
python verify.py reports/report-<时间戳>.json
```

输出：`reports/verify-<时间戳>.md`，分「已证实 / 疑似 / 全部探测明细」三段，每条带证据片段。

## 四步流水线详解

### 第一步：爬虫（crawl.py）

- 同源 BFS 抓取页面
- 自动提取「攻击面候选点」= URL 查询参数 + 表单字段
- 支持 `--max-pages` 限制爬取深度
- 支持 `--no-ai` 只爬不判（不消耗 AI 额度）

### 第二步：AI 判定（llm.py）

- 候选点分批交给大模型
- 输出：漏洞类型 / 可能性 / 理由 / 下一步建议
- Prompt 走文件，避免编码问题
- 支持豆包 CDP 通道（走用户已付费的桌面版额度）

### 第三步：非破坏性验证（verify.py）

`scan.py` 只给**线索**；要回答「能不能攻击成功」必须真发请求。`verify.py` 做这件事，但把「安全」写死在代码里：

| 禁令 | 实现 |
|---|---|
| **不改数据** | 载荷经过 `FORBIDDEN` 正则拦截：出现 `DROP/DELETE/UPDATE/INSERT/ALTER/TRUNCATE/ATTACH/PRAGMA/EXEC/...` 直接抛异常 |
| **不爆破、不压测** | 不做密码猜测、不高并发；每次请求固定 `sleep 0.35s` |
| **默认只读** | 只发 GET；仅「登录类」端点允许 POST，且用不存在的账号（不产生数据）；其它写端点一律跳过并标注 |

探针类型（都是「证明即停」，不构造利用链、不取数据、不落文件）：

- **反射检查**（XSS）：提交带标记的 HTML 载荷，看是否原样回显且尖括号/引号未编码
- **SQL 报错特征**：提交单引号，匹配数据库错误特征（与 Python 堆栈分开归类）
- **SQL 布尔差异**：`1 AND 1=1` vs `1 AND 1=2` 对比响应长度（只读）
- **越权枚举**（IDOR）：不带任何登录态对比 `id=N` 与 `id=N+1` 的返回
- **未授权访问**：无凭据请求敏感页，检查是否返回个人信息特征
- **安全响应头**：缺失 CSP / X-Frame-Options / X-Content-Type-Options（信息类）

### 第四步：报告生成（report_gen.py）

- Markdown 报告 + 原始 JSON 数据
- 每条漏洞带：位置、类型、可能性、AI 理由、验证结果、证据片段
- 支持按严重程度排序

## 安全护栏（guard.py）

`guard.py` 解析域名后**逐个 IP** 校验，**只允许 localhost / 内网**：

- 127.x.x.x
- 10.x.x.x
- 172.16.x.x - 172.31.x.x
- 192.168.x.x
- link-local 地址

公网目标一律拒绝。

```
✅ 允许: http://127.0.0.1:8099/
✅ 允许: http://192.168.1.100:8099/
❌ http://example.com/   → 解析到公网 → 拒绝
❌ http://baidu.com/     → 解析到公网 → 拒绝
```

## 自带烟测靶场

`labtest/app.py` 是一个故意埋了 6 类洞的最小站点，只监听 `127.0.0.1`：

- 反射型 XSS
- 越权 IDOR ×2
- SQL 注入 ×2
- 表单无 CSRF token

开箱即测，不需要额外环境。

## 实测结果

对自带烟测靶的测试结果：

| 指标 | 结果 |
|---|---|
| 爬取页面 | 5 |
| 攻击面候选点 | 5（3 个 URL 参数 + 2 个表单字段） |
| AI 判定 | 1 批，全部返回 |
| **命中率** | **5/5**（反射型 XSS、越权 IDOR ×2、SQL 注入 ×2，另标出「表单无 CSRF token」） |

AI 判定示例（`/api/user?id=1`）：

> 漏洞类型：越权 IDOR ｜ 可能性：高
> 理由：API 按 id 直接返回用户数据，若未校验当前登录用户与目标 id 的归属关系即存在水平越权。
> 下一步：登录普通用户后将 id 改为其他用户 id（如 2），对比返回内容是否泄露他人信息。

## 已知限制（都是刻意的）

- **只做 GET 爬取**，不执行 JS（要渲染动态站再接 Playwright）
- **AI 判定是线索不是结论**，误报需人工复核
- **不自动发攻击请求**：只做「判定」和「非破坏性验证」，不构造完整利用链
